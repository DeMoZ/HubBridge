# Proposal

## Open questions

Defaults are taken so the plan can go ahead; each one can be changed before `/opsx:apply`.

1. **Android screens.** Default: out of scope. Only the Android launcher icon is redrawn with
   the new mark and palette; the control screen keeps the platform DayNight theme (reasons in
   design.md, decision 9). Say so if the phone screen should be redesigned too: that is a
   separate change (new Kotlin view code), not a CSS pass.
2. **Theme switch.** Default: the window follows the system light/dark setting only, like
   UsbMemoryChecker; there is no settings page yet (ROADMAP "settings page" stays open). A
   manual switch would come with that page.
3. **Order with the other two changes.** Recommended order: this change first, then
   `release-pipeline` (the `.app` uses the icon made here), then `desktop-updates-donate` (its
   pills and sheets use the components defined here). They can share one branch/PR or go as
   three PRs in that order.

## Why

The first public release of HubBridge ships the desktop window to people who have never seen
it. Roman asked for a redesign "according to the trends of the year 2035, as it might
plausibly look". Today's page is a quick copy of UsbMemoryChecker's aurora-glass style: three
drifting blurred blobs, a rainbow gradient on every primary button, uppercase panel headings,
no visible keyboard focus, no reduced-motion handling for the background, and a light theme
whose faint text (`#8a8fa5` on white, 3.3:1) fails WCAG AA. The window has no app icon either,
which the packaged `.app` needs.

## What Changes

- **New visual language "Ambient Glass"** for `crates/desktop/src/ui/index.html`: one token
  set (colors, type scale, radii, elevation, motion) for a dark and a light theme, both
  following the system appearance; calm layered glass instead of drifting color blobs; one
  signature accent instead of rainbow gradients everywhere.
- **Layout shell refresh:** a slimmer top bar with the brand mark, a central "link island"
  that shows the connection state, and an empty right-hand action slot (the update and Support
  pills of `desktop-updates-donate` go there); the two-column body stays, with sentence-case
  section titles and count badges.
- **Restyled screens and components:** connection hero (idle path of three steps,
  connecting, needs pairing, connected with a larger round-trip readout and an area
  sparkline), phone and agent cards, USB device cards with the serial row, fields, buttons,
  chips, the PIN sheet and toasts. Same data, same actions, same requests to Rust.
- **Accessibility:** WCAG 2.2 AA text contrast in both themes (checked by a unit test on the
  color tokens), visible keyboard focus, Escape and backdrop close the sheet, reduced motion,
  increased contrast and reduced transparency preferences honored.
- **App mark:** a new logo glyph in the page, an app icon (`AppIcon.icns`, 1024 px PNG)
  generated by a script, and the Android launcher icon redrawn with the same mark.
- **Guard tests** on the page source: no top-level `ipc` declaration, nothing loaded from the
  network, contrast of the theme tokens.
- No new runtime dependencies, no CDN, no web fonts: system fonts only.

## Impact

- Code: `crates/desktop/src/ui/index.html` (CSS rewritten, markup of the shell and the render
  functions adjusted, JS logic and requests unchanged), `crates/desktop/src/main.rs` (page
  guard tests), new `crates/desktop/assets/`
  (`icon.png`, `AppIcon.icns`), new `scripts/make-icon.swift` + `scripts/make-icon.sh`,
  `android/app/src/main/res/mipmap-anydpi-v26/ic_launcher*.xml` (adaptive icon) with
  `drawable/ic_launcher_{background,foreground,monochrome}.xml`.
- No protocol, host library or agent changes; no new crates.
- Docs: `docs/ARCHITECTURE.md` (desktop window section: tokens, theme hook for checks), `docs/ROADMAP.md`
  (desktop window), `README.md` / `README.ru.md` (screenshot), `docs/ARCHITECTURE.md`
  (repository layout: assets, scripts).
