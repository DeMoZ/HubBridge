# Tasks

Specs: `specs/phone-displays/spec.md`, `specs/screen-mirroring/spec.md`, `specs/desktop-window-design/spec.md`.
How: `design.md` (D1…D15 below refer to its decisions).

Rules for every task: `Message` variants are only appended (after `DeviceClosed`); hellos, key derivation and
record framing do not change and `PROTO_VERSION` stays 1. Never print `host.json` or `agent-state.json`. Every
manual simulator or CLI run uses a scratch `HUBBRIDGE_HOME=<scratch>` and `--state-dir <scratch>`. The page
script never declares a top-level `ipc`, dev scripts never declare a top-level `const t` (wrap them in a block),
and the WebView is touched on the main thread only. JSON field names sent by Kotlin match the Rust structs (a
test holds them). macOS-only code sits behind `cfg(target_os = "macos")`; Windows keeps compiling (CI). adb
commands use the user's adb with a timeout on each command (`adb -s 192.168.1.108:5555 …`). Tasks marked
**[Roman]** need Roman to look at the monitor or the phone, or to grant a permission; the executor prepares
everything and asks for exactly that step. Installing a debug build on the phone is allowed in groups 1, 10, 11
and 12 (the installed app is a debuggable build signed with this Mac's debug key; if `adb install -r` reports a
signature mismatch, stop and ask Roman — an uninstall forgets the paired computers).
